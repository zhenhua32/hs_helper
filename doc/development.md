# 开发与使用说明

更新日期：2026 年 10 月 31 日。

当前实验版已贯通本地记牌、固定局面 AI 工具、计划与笔记、建议归档和历史回放。完整第一版验收仍见[开发清单](implementation-plan.md)，离线检查不能替代国服画面对照。

AI 页支持本次自由提问及抢血/解场、起手留牌、比较候选的快捷入口。问题变化会使旧建议失效，问题与建议一起脱敏归档；命令行可用 `--question`，原 `--task` 中的额外文字也会保留为玩家问题。任务模板和当前阶段仍限制可用工具与动作，赛前计划不会开放实时动作或概率计算。

桌面分析会自动承接最多四轮已归档的问题和解释，只读取同一对局、套牌与卡库版本、且不超过当前状态/事件与知识截止边界的记录。旧解释只提供对话背景，当前快照与本次工具结果仍是依据；归档同时记录本次模型请求与引用的旧建议，便于核对来源。

## 构建与运行

需要 Windows 与 .NET 10 SDK。首次恢复需要网络下载 SQLite 依赖。

```powershell
./scripts/verify.ps1
./scripts/run.ps1
```

脚本默认把构建输出放在 .local/build，避免覆盖正在运行的旧版 bin 文件。支持 -ArtifactsPath .local/build-current；验证和启动应使用同一路径。如 `.local/sdk/dotnet.exe` 存在，脚本优先使用该本地 SDK，否则使用系统 PATH。运行数据默认在 %LOCALAPPDATA%\HsHelper，也可使用 ./scripts/run.ps1 -DataDirectory .local/demo-data。SDK 用户目录、NuGet 缓存、构建输出和运行数据留在 Git 之外。

## 模型配置

在仓库根目录创建 .env，可复制 [.env.example](../.env.example) 后填写 api_url、model_name、api_key。支持等价的大写别名，只按文本读取，不执行变量展开。地址可填基础路径 /v1 或完整 /v1/chat/completions；只接受 HTTPS，本机服务允许 HTTP。

启动时先查找 .env，没有时读取本地加密配置。“AI 教练”可重新加载、检查连接及加密保存，也可打开模型与预算设置。加密使用 Windows DPAPI 当前用户。.env 本身仍是用户管理的明文文件，已被 Git 忽略。界面使用密码框，诊断与审计不输出密钥和接口返回正文。

以下为可选调优字段，数值需为表内范围的整数。省略时优先使用已保存的调优值，没有保存值则用默认值；`.env` 显式填写的字段在重新加载或下次启动时优先。接口、模型名称与密钥仍以 `.env` 为准，合并调优不会替换这些字段。界面本次修改会立即应用并加密保存，重新加载时再按上述优先级合并。

| .env 字段 | 默认值 | 允许范围 |
| --- | --- | --- |
| MODEL_MAX_TOOL_ROUNDS | 2 | 0–4 |
| MODEL_MAX_OUTPUT_TOKENS | 1500 | 100–8192 |
| MODEL_TIMEOUT_SECONDS | 30 | 1–120 秒 |
| MODEL_MAX_REQUESTS_PER_MATCH | 60 | 1–10000 |
| MODEL_MAX_TOKENS_PER_MATCH | 200000 | 1–100000000 |
| MODEL_MAX_CONCURRENT_REQUESTS_PER_MATCH | 1 | 1–8 |

也支持去掉 `MODEL_` 前缀的短名；同时填写时，带前缀的字段优先。示例使用默认值，不包含真实配置：

```dotenv
MODEL_MAX_TOOL_ROUNDS=2
MODEL_MAX_OUTPUT_TOKENS=1500
MODEL_TIMEOUT_SECONDS=30
MODEL_MAX_REQUESTS_PER_MATCH=60
MODEL_MAX_TOKENS_PER_MATCH=200000
MODEL_MAX_CONCURRENT_REQUESTS_PER_MATCH=1
```

“检查连接”只发送固定连接检查文本，不发送对局。分析使用紧凑玩家视角投影：当前公开场面、我方手牌、选择、区域数量、牌库追踪、近期公开事件及相关基础牌效。完整快照留在本机执行规则验证；模型上下文不复制整库 RawJson、隐藏牌库实体槽位或原始事件 DataJson。请求 JSON 保留中文字面量，避免重复的 Unicode 转义；这项压缩不代表已经保证特定响应速度或费用。

自动建议默认关闭；开启后才在实时稳定决策点发送请求。协议是 Chat Completions 工具调用，服务需支持对应工具协议与 JSON 输出，参见 [Function calling 官方说明](https://developers.openai.com/api/docs/guides/function-calling)。

## 桌面流程

1. 中文卡库页可同步最新 zhCN 数据；诊断或连接日志后，使用“同步客户端版本卡库”下载观察到的固定 build。也可导入有明确数字 build 的 HearthstoneJSON。同步实时版本不改写已选历史局面使用的卡库版本。支持名称、效果与关键词搜索、图片缓存。
2. 套牌页首用载入用户提供的“野兽快”：30 张主牌、3 张边栏。解析可查看名称和费用曲线，保存到套牌库创建不可变版本并保留边栏；导出 JSON 是独立入口。
3. 对局页确认“记录套牌”，诊断路径或填入 Logs/Power.log，开始监听或导入。启动时固定套牌版本，修改草稿不改写已记录的对局。
4. 自动视角仅在起手阶段有唯一且充分的私有手牌证据时确认；证据不足保持未知。可手动选择 1 或 2，切换会先停止并保存。
5. 悬浮窗默认隐藏，显示我方手牌、已知剩余牌库、对手公开出牌台账、建议和质量。支持拖动、缩放、穿透与设置。Ctrl+Shift+H 显隐、Ctrl+Shift+A 分析、Ctrl+Shift+T 穿透；冲突显示在主窗口。
6. AI 页确认局面 build 与配置，请求留牌、回合、选择或复盘建议；计划入口提供不依赖实时局面的赛前套牌分析。五种任务使用各自模板，记录模板版本。历史分析绑定当时卡库和套牌，缺少对应版本时不会提供已验证牌效。
7. 记录页通过上一页/下一页访问匹配筛选的全部对局，每页 100 条，显示页码、条数和是否还有记录；切换 build、套牌版本、对手职业、先后手或天梯筛选会重查第一页。选择一局和一个决策点，可查看当时快照、事件与建议归档并请求分析。统计默认仅国服标准猎人天梯，保留完整筛选范围的样本量，不只统计当前页。记录时间是观察/导入时间，不能当作原始游戏时间。
8. 在计划与笔记入口选择已保存的套牌版本，创建赛前计划或对局笔记，可按对手职业和先后手限定适用范围。列表每页 100 条，可按类型和字面标题片段筛选、前后翻页；空格、符号按原样匹配，区分大小写。翻页固定首屏资料时间，刷新与筛选重回第一页。修改与删除保留旧版本，关键回合标记仍绑定原对局与事件序号。
9. 已完成建议自动归档，记录局面、事件序号、build、任务模板版本、验证状态与简短工具依据。可从对局或套牌计划入口查看；归档是事后资料，不作为较早决策点可见的信息。

计划/笔记编辑器独立于当前列表页与筛选，翻页不会覆盖草稿；切换条目、套牌、新建或关闭前须保存或明确放弃修改。保存时仍绑定原条目及套牌，筛选不匹配的已保存条目保留在编辑器并说明当前位置。干净编辑器在刷新时可采用外部新版本；有草稿时保留文本并提示版本差异，明确放弃会按 ID 重读最新版本，外部删除则退出该条目，历史版本仍可查询。关闭期间取消资料查询并拒绝迟到结果，正在保存或有未保存草稿时窗口保留打开并说明原因。

`get_matchup_plan` 对计划和笔记分别检索，先各保留 10 条，余位先补剩余计划再补笔记，合计最多 20 条。每类先按固定资料时刻选择条目的最新版本，再排除删除、错误范围和当前局未来事件；适用已知对手职业/先后手的匹配数优先，随后按保存时间与条目标识稳定排序，最后才应用有界查询。每类最多读取 20+1 项，返回数量下限及截断标记，不把该下限当全库总量；正文仍最多 1600 字。模型不能指定类型、标题、套牌、查询截止或事件截止，用户内容仍只作参考意见。
10. 停止、切换或退出会保存尚未落盘的记录并结算分析用量。保留期限清理只移除旧已结束对局，不删除未完成局、卡库或套牌。

对局页按双方分区展示中文卡名、观察到的英雄生命/护甲、法力、武器、技能、手牌与场面；未观察到的动态属性保持未知。下方展示已知剩余牌库及精确/下限限制、当前确认的我方选择候选及数量要求，以及局面质量。“本地概率与动作计算”无需模型配置，可固定局面计算抽牌概率、核对动作顺序、有限斩杀搜索或选择范围；结果始终保留覆盖范围和未知限制。停止监听、日志追赶或停更时不会把旧局面当作当前可执行步骤，可选择“复盘最后观察局面”或“从日志重建局面”。“日志配置预览”提供备份启用与恢复，修改后由使用者在方便时重启游戏。

现代武器更新将 build 255790 的当前剩余耐久统一为已观察的 `HEALTH-DAMAGE`，双方武器展示、紧凑上下文和动作结果使用同一份证据。已装备武器缺少任一现代字段或其数值/别名存在反证时保持未知；旧 `DURABILITY` 和卡库印刷数值不补齐当前耐久，也不与现代数值相加或重复折损。其它或未知 build 不自动猜测旧版协议。

普通英雄攻击可消耗一次现代武器耐久，最后一次使用会损毁武器并移除其攻击贡献；已确认的独立英雄攻击和风怒按当前证据处理。简单武器可按当前费用、攻击和最大耐久装备，成功新装备才显式建立 `DAMAGE=0`。未知战吼、过载或使用时效果在支付前拒绝；未知损毁亡语、替换结算或无法区分来源的风怒会停在武器观察边界，不能用中间投影继续动作或证明斩杀。详情见[武器计算边界](hunter-rule-coverage.md#计算与验收边界)。这些改动自 preview10 起已包含在发行包中。

阿迦玛甘的生命支付会单独列出当前费用和对手生命变化，不计入普通伤害；费用超过 10 不可用。支付致死后停止计算该牌后续效果，结果中的手牌区域保留最后观察状态。具体逐牌范围见[野兽快牌效覆盖](hunter-rule-coverage.md)。

本地计算可选择当前候选并“评估选择直接后果”，显示追踪术、下水道之王或地图的直接入手、减费和牌库变化；保留最终费用与后续触发未知。动作编辑器支持“结束回合”，自动绑定当前我方玩家且禁用额外目标。神秘恐魔在单来源、2–7 个敌方随从时可列出有限相关终局及见证战斗顺序，生命、吸血和存活必须按同一分支比较。见证顺序不表示客户端实际顺序或概率；多目标 Line 的主体场面仍停在触发前，不应用任何有利分支。未知触发和普通攻击就绪字段继续保留边界，多个恐魔的完整结算仍未覆盖。所有结果只作用于固定局面，既不操作游戏也不作为选择后新局面的替代。

追踪术、地图、玛洛恩、下水道之王、寻回机和迅猛龙先锋已有原生使用入口：动作验证会核对固定来源与当前身份后支付、离手或入场，再停在真实发现/拼装/回溯选择前。追踪术明确空库时本次无需选择且不产生抽牌疲劳；缺少计数不当作空库。战吼被抑制时仍可核验普通入场，迅猛龙先锋的独立回溯另行判断。选择尚未观察时不能继续使用假想的新牌；生命支付先致死则停止本体和牌效。

选中宝石鹦鹉手牌后可“预览随机生成数量”，显示本体离手后的直接入手与满手损失，不把生成当成抽牌。选中巨狼祝福技能可“比较巨狼祝福分支”，逐一查看当前野兽手牌命中后的攻击/费用，缺失当前值保持未知。多个随机候选互斥，不能选择实际命中或拼合结果；顺序验证在随机生成或多候选祝福处等待新局面，单一已知祝福候选仍可确定结算。

在动作编辑器选择我方场上原生熔岩猎犬和敌方随从作为攻击对象，可点击“预览熔岩猎犬分配”。工具复用普通攻击校验与基础交换，再按当前攻击力逐包列出有限的后置分支、目标伤害/生命/护甲区间，以及圣盾和吸血等已覆盖变化。攻击对象不是随机命中，不能手选分配结果或拼接各目标的有利区间。合法性未知、枚举截断及未展开触发会明确提示；该预览不改变局面、不证明斩杀。多目标顺序投影停在基础交换后，实际随机命中未观察时不得继续动作；只有完整状态已审计的唯一敌方英雄情形仍可确定结算。

“我方陷阱来袭预览”使用独立下拉框选择已安装的我方爆炸陷阱和敌方公开场上角色，点击“预览爆炸陷阱来袭”；普通我方动作编辑器不会混入敌方来源。攻击对象固定为我方英雄，只假设来袭发生，不执行对手动作。当前为对手回合时可预览本次直接群伤、盾/甲/免疫及来袭者或其英雄直接死亡后的停止；我方回合明确显示当前不触发，不把输入移到未来回合。法强取触发时归属者的当前证据，不用安装时法强或下一法术临时加成。未知受伤触发、亡语、复生、额外修正或其他奥秘顺序继续等待观测，直接存活不证明完整攻击会继续。工具不查询对方奥秘、不修改局面，也不能认证敌方攻击合法、实际发生、后续己方动作或斩杀。

“预览使用后触发”同时展示原生发现、拼装、回溯入口，以及所选手牌对当前围攻城门进度的影响、已确认梦缚迅猛龙的来源/目标和次数范围。该工具只接受当前我方手牌实体，不允许手填计数、候选、任务进度或随机词条。发现入口以成功离手为条件，使用后触发以前置效果完成为条件，不能把两段拼成已发生的完整局面。动作顺序支持先安装围攻城门再连续使用符合条件的牌，达到三张后等待实际奖励选择；本体发现、战吼、抽牌或未展开触发尚未完成时，只显示后置条件预览。缺计数不补零，缺当前伤害不当作健康零伤；迅猛龙自身注册与完整词条池仍未知。

地图的追加条件只接受真实首选、同一实体在原己方回合的实际 HAND 使用，以及随后实际提供的原始剩余两项；当前预览只再选一张，不重发首选。使用同名的另一实体或猜测新入手实体关联无效。顺序验证可以记录已确认首选实体的本地模拟使用，但仅作为追加请求等待新日志，不写进实际出牌历史，也不创建第二张牌。

下水道之王的选择结果分开显示按提供时来源冻结的实际已选和当前提供候选。辅助评估器可显式接收起始牌码，只作初始参考；当前界面未自动绑定该参考。历史有缺口时次数只是已观察下限，已选也不等于成功入手；当前候选和初始三张均不代表完整剩余池。重复战吼、复制、偷取及换实体后的池继承仍未知，不能据此算出下一次全部可选牌。

## 计划、笔记与历史查询

历史列表以记录时间倒序、同时间按对局 ID 排序，每次最多读取一页加一条探测记录，不一次加载全部对局。首屏固定浏览时间上界，翻页期间新记录不会把原页面挤动；刷新回第一页并纳入新记录。延迟返回的旧页或旧筛选不能覆盖新列表。换页成功会清除列表选择和旧的待加载决策点，但保留已经固定的历史快照及其明确标识；选择新对局后才切换复盘范围。

个人计划和笔记属于用户保存的意见，不能证明当前对手持有某张牌。实时分析固定请求开始时刻，历史复盘固定所选决策点的记录时刻；个人工具不能把这个截止时刻移到现在。同一对局的笔记还受事件序号限制，之后编辑的版本和之后标记的回合不会进入更早的查询。

个人战绩使用截止时刻已经保存、并已结束的快照重新统计，排除当前局，不读取当前数据库中后来补齐的最终结果来回答过去的问题。查询同时固定 build、套牌版本、模式和适用的对手职业/先后手；胜率只描述个人样本，不是当前局获胜概率。数据库中的时间是观察或导入时间，不能据此声称还原了原始游戏时间。

## Agent 与计算边界

卡池规则可附带独立的 `Construction` 构筑证据，限定同一 build/模式及父规则有效期内的卡组总数限制、边栏容量、显式允许成员和职业豁免。同步固定 build 255790 时，只在 CardDefs 标签一致的情况下附加古神总数最多一张、下水道之王边栏最多三张的已审核约束。私藏子集尚未完整展开，未提供经核对的成员名单、同名或最小数量规则时仍为 Unknown；部分构筑证据不代表完整国服卡池合法。

卡库升级到数据格式 3，保留旧版卡牌、卡池 JSON 和原哈希。旧版助手会拒绝打开升级后的卡库，避免忽略新增约束；需要回退时使用升级前的数据目录备份。真实日志、缓存和模型配置不随规则入库或提交。

每次分析绑定 MatchId、StateVersion 与卡牌 build。

| 工具 | 行为 |
| --- | --- |
| get_snapshot | 固定玩家视角局面与质量 |

规则覆盖基础战斗、费用与部分 build 255790 猎人牌效。模型出牌和攻击动作由主机再次校验：只有 Verified 且合法才显示动作；Conditional/Unsupported 移除动作并显示风险；Invalid 拒绝。确定斩杀只来自完整覆盖的规则结果。全为 choose 的动作组单独验证，界面标为“选择范围已验证”，并保留“未模拟选择后效果”的风险；选择与出牌混合的序列仍不支持。

当前工作区回合与选择任务模板分别为 `hunter-v14/turn`、`hunter-v14/choice`；其它任务基础模板仍为 `hunter-v4`。策略保留熔岩猎犬、爆炸陷阱和武器的观察边界，并要求神秘恐魔按同一相关分支比较见证顺序、场面和治疗；截断、前缀或保留的普通就绪字段不能作为权威后继状态或斩杀依据。结束回合的模型动作必须以我方玩家实体 ID 为来源、不能带目标；模型解析、工具参数和最终主机验证使用同一约定。候选身份经过统一的视角、稳定性、数量及实体冲突边界，观战时不外发私有手牌、奥秘、牌库组成或私有事件身份。

围绕“野兽快”已增加苦花骑士、振翅守卫的灌注战吼、幽爪熊的入场与原生灌注亡语。已有巨狼祝福且观察到一致可靠的当前参数时可计算强化；仅有一个已确认、当前攻击力与费用已知的野兽候选时，技能的加攻和减费才有确定结果。首次技能替换的强度或可用状态不明时保留条件，不凭印刷初值补齐。

奇异训犬师可计算入场、直接抽牌范围和有证据的后置灌注，但不猜抽到的野兽；花木护侍依据明确累计灌注判断是否抽两张，缺计数仍保留范围，不从技能等级推算。震地雷龙可给已知当前属性的手牌/牌库随从结算 +3/+3，隐藏目标保持未知；已审计的纯属性附魔使用观察值，不重复叠加。原生发现入口和部分实际选择生命周期已有覆盖，完整发现池、拼装主目标及新实体映射、旧局面回溯、复杂随机与奥秘交互仍未完成，不能据此宣称整套牌已可完整模拟。

牌库跟踪需要从开局持续观察且与确认套牌一致。晚接入、缺口和未知洗入会保留未知量，已知数量可能退化为下限，不伪造精确概率。对手台账记录公开的 HAND→PLAY 事件，回手后再打分别记录；衍生物不自动算作打出的牌，未知身份不使用未来信息回填历史。

默认每次分析最多 2 轮工具交互、总计 8 次工具调用、30 秒，每次 HTTP 输出上限 1500 令牌；按 MatchId 默认限制 60 次 HTTP 请求、200000 令牌、1 个并发。工具总调用上限为固定保护，其余可用上表配置。修改预算会先取消并结算现有请求，再恢复已经保存的消耗，不以调高或调低配置清零用量。

发送前预留用量，完成后按服务报告结算；实际报告可能超过预留，达到预算后拦截后续请求。未取得成功 HTTP 响应的请求释放令牌预留，但仍计请求次数；取得成功响应后，若缺少用量或无法解析正文，则按保守预留量计入，分析失败不一定代表没有消耗。匿名审计保存模型、build、任务/模板版本、用量、耗时和工具结果哈希；归档另存简短工具依据摘要，不保存完整提示、原始 HTTP 正文或密钥。重启恢复已记录消耗，连接检查不计入对局预算。赛前套牌分析使用对应套牌的独立预算标识。Storage 提供审计详情清理 API，桌面清理入口只清对局记录；两者都不会重置已消费预算。不显示未经核实的费用金额。

局面、来源、视角、套牌、配置或历史选点变化会取消旧请求，返回前再核对。模型故障不停止本地记牌。自动建议等待 1.2 秒稳定，并跳过回放与日志追赶的中间局面。
