# 开发与使用说明

更新日期：2026 年 11 月 1 日。

当前实验版已贯通本地记牌、固定局面 AI 工具、计划与笔记、建议归档和历史回放。完整第一版验收仍见[开发清单](implementation-plan.md)，离线检查不能替代国服画面对照。

AI 页支持本次自由提问及抢血/解场、起手留牌、比较候选的快捷入口。问题变化会使旧建议失效，问题与建议一起脱敏归档；命令行可用 `--question`，原 `--task` 中的额外文字也会保留为玩家问题。任务模板和当前阶段仍限制可用工具与动作，赛前计划不会开放实时动作或概率计算。

桌面分析会自动承接最多四轮已归档的问题和解释，只读取同一对局、套牌与卡库版本、且不超过当前状态/事件与知识截止边界的记录。新源码还要求建议来自当前可见性版本；无标记或不同版本的旧建议仍可浏览，不再进入新请求。旧解释只提供对话背景，当前快照与本次工具结果仍是依据；归档同时记录本次模型请求与引用的旧建议，便于核对来源。

## 构建与运行

需要 Windows 与 .NET 10 SDK。首次恢复需要网络下载 SQLite 依赖。

```powershell
./scripts/verify.ps1
./scripts/run.ps1
```

脚本默认把构建输出放在 .local/build，避免覆盖正在运行的旧版 bin 文件。支持 -ArtifactsPath .local/build-current；验证和启动应使用同一路径。如 `.local/sdk/dotnet.exe` 存在，脚本优先使用该本地 SDK，否则使用系统 PATH。运行数据默认在 %LOCALAPPDATA%\HsHelper，也可使用 ./scripts/run.ps1 -DataDirectory .local/demo-data。SDK 用户目录、NuGet 缓存、构建输出和运行数据留在 Git 之外。

## 模型配置

在仓库根目录创建 .env，可复制 [.env.example](../.env.example) 后填写 api_url、model_name、api_key。支持等价的大写别名，只按文本读取，不执行变量展开。地址可填基础路径 /v1 或完整 /v1/chat/completions；只接受 HTTPS，本机服务允许 HTTP。

启动时先查找 .env，没有时读取本地加密配置。“AI 教练”可重新加载、检查连接及加密保存，也可打开模型与预算设置。加密使用 Windows DPAPI 当前用户。.env 本身仍是用户管理的明文文件，已被 Git 忽略。界面使用密码框，诊断与审计不输出密钥和接口返回正文。

以下为可选调优字段，整数项需在表内范围。省略时优先使用已保存的调优值，没有保存值则用默认值；`.env` 显式填写的字段在重新加载或下次启动时优先，包括 `false` 和 `omitted`。接口、模型名称与密钥仍以 `.env` 为准，合并调优不会替换这些字段。界面本次保存会应用并加密保存，重新加载时再按上述优先级合并。

| .env 字段 | 默认值 | 允许范围 |
| --- | --- | --- |
| MODEL_ENABLE_TOOLS | true | true / false |
| MODEL_RESPONSE_FORMAT | omitted | omitted / json_object / json_schema |
| MODEL_MAX_TOOL_ROUNDS | 2 | 0–4 |
| MODEL_MAX_OUTPUT_TOKENS | 1500 | 100–8192 |
| MODEL_TIMEOUT_SECONDS | 30 | 1–120 秒 |
| MODEL_MAX_REQUESTS_PER_MATCH | 60 | 1–10000 |
| MODEL_MAX_TOKENS_PER_MATCH | 200000 | 1–100000000 |
| MODEL_MAX_CONCURRENT_REQUESTS_PER_MATCH | 1 | 1–8 |

也支持去掉 `MODEL_` 前缀的短名；同时填写时，带前缀的字段优先。示例使用默认值，不包含真实配置：

```dotenv
MODEL_ENABLE_TOOLS=true
MODEL_RESPONSE_FORMAT=omitted
MODEL_MAX_TOOL_ROUNDS=2
MODEL_MAX_OUTPUT_TOKENS=1500
MODEL_TIMEOUT_SECONDS=30
MODEL_MAX_REQUESTS_PER_MATCH=60
MODEL_MAX_TOKENS_PER_MATCH=200000
MODEL_MAX_CONCURRENT_REQUESTS_PER_MATCH=1
```

“检查连接”只发送固定连接检查文本，不发送对局。分析使用紧凑玩家视角投影：当前公开场面、我方手牌、选择、区域数量、牌库追踪、近期公开事件及相关基础牌效。完整快照留在本机执行规则验证；模型上下文不复制整库 RawJson、隐藏牌库实体槽位或原始事件 DataJson。请求 JSON 保留中文字面量，避免重复的 Unicode 转义；这项压缩不代表已经保证特定响应速度或费用。

自动建议默认关闭；开启后才在实时稳定决策点发送请求。协议是 Chat Completions。工具开关关闭时，完全省略 `tools` 和 `tool_choice`，只发一次分析请求；服务仍返回工具调用时拒绝执行，已报告用量仍结算。`MODEL_MAX_TOOL_ROUNDS=0` 只禁止交互轮次，保持发送工具定义和 `tool_choice=none`，不能代替禁用工具。重新开启工具会保留已设置轮数。

输出默认 `omitted`，仅用提示要求 JSON，不发送 `response_format`；`json_object` 请求 JSON 对象，`json_schema` 请求固定严格结构。后两种需服务明确支持，不自动探测、回退或重发另一格式。严格结构分策略与候选动作两类，连接检查使用策略结构；主机仍独立检查字段、实体、合法性、局面时效、规则覆盖和斩杀，格式支持不能替代这些验证。工具和输出能力契约见 [Chat Completions 官方接口](https://developers.openai.com/api/reference/resources/chat/subresources/completions/methods/create)与[结构化输出说明](https://developers.openai.com/api/docs/guides/structured-outputs?api-mode=chat)。

加密保存使用配置格式 2，新程序可读取原格式 1 并沿用开启工具、提示 JSON 的旧默认；读取不会自动改写旧文件，下次明确保存才升级。旧程序会拒绝格式 2，避免静默忽略能力选择。CLI 的 `model-check --env path --data-dir path` 与 `advise` 合并同一目录中已保存的调优，连接检查只说明本次所选模式的固定请求被接受，不证明完整工具交互或策略质量已验收。

桌面设置的保存操作会先取消旧请求并应用本次设置，再加密写入。写入失败时面板保留打开并明确提示当前已应用、尚未保存，可重试；关闭面板不回滚已应用的设置。未点击保存就取消则不改变当前配置。

## 桌面流程

1. 中文卡库页展开“卡库导入与同步”可同步最新 zhCN 数据；诊断或连接日志后，使用“同步客户端版本卡库”下载观察到的固定 build。也可导入有明确数字 build 的 HearthstoneJSON。同步实时版本不改写已选历史局面使用的卡库版本。支持名称、效果、CardId 与关键词搜索，以及可收藏、全部、不可收藏三种筛选；结果最多展示 200 张，超过时提示缩小筛选。不可收藏模式会关闭并禁用只包含可收藏牌的标准系列筛选。改变筛选后点击搜索或按回车。详情显示搜索时固定 build 的文字、身份和收藏属性，直接关联记录每页 100 项，可打开并返回上一张，最多保留 32 步返回历史；关联查询不受当前职业或收藏筛选影响，缺项不借其它版本补齐，也不自动递归展开。没有关联记录不代表没有衍生牌，已有记录也不是完整生成池或概率。图片只作最新浏览辅助，不能代替固定版本文字。切换筛选、卡牌、卡库或关闭时会取消旧读取并拒绝迟到结果。
2. 套牌页首用载入用户提供的“野兽快”：30 张主牌、3 张边栏。解析可查看名称和费用曲线，保存到套牌库创建不可变版本并保留边栏；另可导出 JSON 或包含边栏的纯牌码文本。JSON 中的牌码与已选保存版本完全一致时，保留原名称、版本 ID、卡库 build、创建时间和前版 ID；修改主牌、边栏、英雄或模式后按未保存草稿导出，来源版本与 build 留空，不用当前活动卡库替代。导出不会创建套牌库版本，纯牌码不携带这些来源信息。
3. 对局页确认“记录套牌”，诊断路径或填入 Logs/Power.log，开始监听或导入。启动时固定套牌版本，修改草稿不改写已记录的对局。
4. 自动视角仅在起手阶段有唯一且充分的私有手牌证据时确认；证据不足保持未知。可手动选择 1 或 2，切换会先停止并保存。
5. 悬浮窗默认隐藏，显示我方手牌、已知剩余牌库、对手公开出牌台账、建议和质量。支持拖动、缩放、穿透与设置。Ctrl+Shift+H 显隐、Ctrl+Shift+A 分析、Ctrl+Shift+T 穿透；冲突显示在主窗口。
6. AI 页确认局面 build 与配置，请求留牌、回合、选择或复盘建议；计划入口提供不依赖实时局面的赛前套牌分析。五种任务使用各自模板，记录模板版本。历史分析绑定当时卡库和套牌，缺少对应版本时不会提供已验证牌效。
7. 记录页通过上一页/下一页访问匹配筛选的全部对局，每页 100 条，显示页码、条数和是否还有记录；切换日期、build、套牌版本、对手职业、先后手或天梯筛选会重查第一页。日期按本机首次观察/导入时间筛选，包含首尾两天；可单边限定、清空，或填入含今天的最近 7／30 个自然日。预设填好具体日期后翻页不滚动变更，刷新仍保留所选日期。无效或倒置日期会清空旧结果并说明原因，修正后重新查询。选择一局和一个决策点，可查看当时快照、事件与建议归档并请求分析。统计默认仅国服标准猎人天梯，保留完整筛选范围的样本量，不只统计当前页；展开各职业战绩可比较胜、负、平、未知与有效胜负样本，胜率为胜数除以胜负总数，平局和未知不计入分母，没有有效胜负时显示样本不足。记录时间不是原始游戏时间，战绩使用读取时已记录的结果。
8. 在计划与笔记入口选择已保存的套牌版本，创建赛前计划或对局笔记，可按对手职业和先后手限定适用范围。列表每页 100 条，可按类型和字面标题片段筛选、前后翻页；空格、符号按原样匹配，区分大小写。翻页固定首屏资料时间，刷新与筛选重回第一页。修改与删除保留旧版本，关键回合标记仍绑定原对局与事件序号。选择已保存的关联笔记后可“打开关联局面”，按原对局与精确事件回看；有未保存草稿时先保存或明确放弃。同一事件有多个实际状态版本时须明确选择，不默认取最后一个；缺精确快照或原局已清理时保留笔记并说明缺项。
9. 已完成建议自动归档，记录局面、事件序号、build、任务模板版本、验证状态与简短工具依据。对局与套牌计划的归档窗口各自固定范围，每页 100 条，可前后翻页、精确筛选任务，或按摘要/当时提问的字面片段搜索；旧空任务与未知任务仍可查。首次打开固定浏览截止，刷新回第一页并纳入新记录，翻页和筛选保留已选详情并说明是否仍在当前页。归档是事后资料，不作为较早决策点可见的信息。

计划/笔记编辑器独立于当前列表页与筛选，翻页不会覆盖草稿；切换条目、套牌、新建或关闭前须保存或明确放弃修改。保存时仍绑定原条目及套牌，筛选不匹配的已保存条目保留在编辑器并说明当前位置。干净编辑器在刷新时可采用外部新版本；有草稿时保留文本并提示版本差异，明确放弃会按 ID 重读最新版本，外部删除则退出该条目，历史版本仍可查询。关闭期间取消资料查询并拒绝迟到结果，正在保存或有未保存草稿时窗口保留打开并说明原因。

`get_matchup_plan` 对计划和笔记分别检索，先各保留 10 条，余位先补剩余计划再补笔记，合计最多 20 条。每类先按固定资料时刻选择条目的最新版本，再排除删除、错误范围和当前局未来事件；适用已知对手职业/先后手的匹配数优先，随后按保存时间与条目标识稳定排序，最后才应用有界查询。每类最多读取 20+1 项，返回数量下限及截断标记，不把该下限当全库总量；正文仍最多 1600 字。模型不能指定类型、标题、套牌、查询截止或事件截止，用户内容仍只作参考意见。
10. 停止、切换或退出会保存尚未落盘的记录并结算分析用量。保留期限清理只移除旧已结束对局，不删除未完成局、卡库或套牌。

对局页按双方分区展示中文卡名、观察到的英雄生命/护甲、法力、武器、技能、手牌与场面；未观察到的动态属性保持未知。下方展示已知剩余牌库及精确/下限限制、当前确认的我方选择候选及数量要求，以及局面质量。“本地概率与动作计算”无需模型配置，可固定局面计算抽牌概率、核对动作顺序、有限斩杀搜索或选择范围；结果始终保留覆盖范围和未知限制。停止监听、日志追赶或停更时不会把旧局面当作当前可执行步骤，可选择“复盘最后观察局面”或“从日志重建局面”。“日志配置预览”提供备份启用与恢复，修改后由使用者在方便时重启游戏。

“复盘最后观察局面”按对局、事件序号、状态版本和内容核对精确保存点，事件、说明、原套牌／卡库和知识截止共同更新，不拼接同序号的较晚版本。有明确观察时间但尚未精确保存的内存局面仍可固定查看；事件仅标为该快照自身的近期信息，不充当已保存时间线。缺少观察时间时保持未知并拒绝依赖历史截止的模型分析，不用当前时间补齐。固定操作保留原实时快照，不自动分析；读取中切局、切历史、换来源或关闭会拒绝迟到结果。

未精确保存时，已有对局记录只使用其原绑定元数据，且须原会话与此帧的明确我方视角一致才保留套牌；当前来源 pin、套牌选择器或草稿不能替换原记录。尚无会话记录时，只有真实最后实时帧与当前引擎同局、同版本、同事件和同视角，才接受该来源已经建立的套牌绑定；引擎自身的兜底快照不借当前 pin 或旧观察时间。普通历史选点也会丢弃迟到的旧失败，返回实时或选择新局面后的提示不被覆盖，当前读取失败仍正常报告。

长对局与聚合预载使用 `GetByIdsBatchedAsync`／`GetByDbfIdsBatchedAsync`，整次固定 build、语言和卡池证据，去重后逐批最多 500 项，成功后返回只读且与 SQLite 全局排序一致的结果；失败或取消不发布部分数据。规则、拼装供体、桌面名称／本地工具／浮层／分析及 CLI 均不再因聚合超过 500 而抛错或静默丢掉后批定义。原单批 API 上限、模型 `get_cards` 的 30 项限制和桌面关联牌每页 100 项不变；缺失定义继续未知，不跨活动版本补齐。

本地动作工具可在添加“使用手牌”后，把同一候选序列中的我方手牌随从选作后续攻击来源，标签明确它仅为候选，攻击资格仍由规则引擎验证；刚使用且没有冲锋／突袭资格的攻击、已结束回合后的动作或其他非法顺序仍被拒绝，突袭也不能因此攻击英雄。移除使用动作或换绑局面后，不保留该攻击候选；改变序列会清除旧验证结果。它不把手牌直接变成实际场面、不生成新实体，也不调用模型。

本地 preview22 新增“预览所选随从亡语抽牌”：在“角色攻击”中选中当前我方场上带实际“心中的恶魔”附魔的随从，查看单次死亡后抽两张的入手、爆牌、疲劳及英雄风险。按钮不会杀死随从，在对手回合也可作条件预览；当前随从原在场，不会腾出一个手牌位。`evaluate_deathrattle_draw` 采用同一规则，已覆盖交换后的 `DrawPreviews` 还使用该前缀实际手牌、牌库及吸血恢复后的生命；实体投影停在抽牌前，不能继续安排第二次攻击或新牌动作。其它未知触发、重复／抑制、原生额外亡语及复生不按单次计算。当前亡语显示“亡语”，数字 217 与重复、抑制标签一同归一；私有属性不因新标签公开。来源补入统一第88条完整定义，该版回合／选择模板为 hunter-v19，其它基础模板为 hunter-v5。

本地 preview24 包含独立的“对手公开手牌记忆”：同一实体曾在公开场上／墓地确认身份并连续进入手牌时，主窗、悬浮窗和历史说明显示其基础中文卡名、公开来源与事件序号。对手实际手牌实体仍隐藏身份与属性，记忆不进入动作实体、当前效果、费用或牌序；私有附魔也不因目标曾公开而变得可见。`public_hand_memory` 与 `get_recent_events` 使用同一对局／状态／事件／观察者核对，卡库只提供固定版本基础定义，隐藏实体的 `get_entity_effect` 仍拒绝；错绑的整份调用方上下文也会被拒绝，避免只删记忆却沿用晚帧卡库选择或事件。旧快照缺字段保持未知且原 JSON／哈希不变，后来公开或同序号后继状态不覆盖旧决策。缺口清除旧记忆，后续新公开事实可在结算后重新追踪并明确可能遗漏，同时保存部分快照而不升级全局质量或稳定决策资格；未知和错绑记忆不预载卡名。裸私有 SHOW／REVEALED 标签不当作新公开证明，直接手牌展示及特殊客户端例外尚待专项核对。回合／选择模板为 hunter-v20，其它基础模板为 hunter-v6，附魔可见性版本仍 attachments-v1；preview24 还包含下述异常块结束与旧记录连续性修复。

## 计划、笔记与历史查询

关联笔记回看固定原局的保存套牌、build、精确状态版本及该快照的录制时刻，知识查询仍以此时刻截止，后来修改的笔记和后来公开的身份不会成为旧局面的已知信息。回看不自动分析或改写笔记；缺卡库或原局未绑定套牌时仍可查看原快照，并保留未知。改变当前条目、编辑草稿、切换历史或日志来源、进入新对局与关闭窗口会拒绝过时的回看请求。

历史库自 preview13 起升级至 schema 3，为新记录事件保存所属状态版本；按决策点读取的快照及事件列表使用同一精确边界。旧事件、快照正文和套牌数据保留，无法归属到状态版本的旧同序号事件不反填或猜测，回看时明确提示并省略这些事件。较早序号的事件仍可查看，旧的按序号查询接口保持原语义。旧版程序不能读取升级后的历史库，回退前需恢复升级前备份。

建议归档详情保留完整日期、原对局/套牌/build、状态与事件、模型和请求来源，以及当时的动作、验证状态和工具依据；旧来源缺失时明确标为未知。动作只以保存的实体编号展示，不借当前卡库或局面补身份，也不修改主建议、悬浮窗或固定历史快照。套牌计划严格使用该版本的独立记录范围，不混入使用同一套牌的实战建议。较晚针对旧局面生成的复盘可在归档窗口阅读，但连续追问仍只承接固定状态、事件、保存时间及知识截止允许的最多四轮。

历史列表以记录时间倒序、同时间按对局 ID 排序，每次最多读取一页加一条探测记录，不一次加载全部对局。首屏固定浏览时间上界，翻页期间新记录不会把原页面挤动；刷新回第一页并纳入新记录。延迟返回的旧页或旧筛选不能覆盖新列表。换页成功会清除列表选择和旧的待加载决策点，但保留已经固定的历史快照及其明确标识；选择新对局后才切换复盘范围。

个人计划和笔记属于用户保存的意见，不能证明当前对手持有某张牌。实时分析固定请求开始时刻，历史复盘固定所选决策点的记录时刻；个人工具不能把这个截止时刻移到现在。同一对局的笔记还受事件序号限制，之后编辑的版本和之后标记的回合不会进入更早的查询。

个人战绩使用截止时刻已经保存、并已结束的快照重新统计，排除当前局，不读取当前数据库中后来补齐的最终结果来回答过去的问题。查询同时固定 build、套牌版本、模式和适用的对手职业/先后手；胜率只描述个人样本，不是当前局获胜概率。数据库中的时间是观察或导入时间，不能据此声称还原了原始游戏时间。

## Agent 与计算边界

卡池规则可附带独立的 `Construction` 构筑证据，限定同一 build/模式及父规则有效期内的卡组总数限制、边栏容量、显式允许成员和职业豁免。同步固定 build 255790 时，只在 CardDefs 标签一致的情况下附加古神总数最多一张、下水道之王边栏最多三张的已审核约束。私藏子集尚未完整展开，未提供经核对的成员名单、同名或最小数量规则时仍为 Unknown；部分构筑证据不代表完整国服卡池合法。

卡库升级到数据格式 3，保留旧版卡牌、卡池 JSON 和原哈希。旧版助手会拒绝打开升级后的卡库，避免忽略新增约束；需要回退时使用升级前的数据目录备份。真实日志、缓存和模型配置不随规则入库或提交。

| validate_choice | 验证当前选择 ID、归属、就绪状态、候选范围、数量和去重；不结算选择后效果 |
| evaluate_choice | 对已确认来源的当前候选推导直接入手、授予减费和直接牌库变化；不生成最终费用或后续动作 |
| evaluate_magma_split | 仅接收来源和攻击对象实体 ID，复用攻击校验并列出熔岩猎犬后置逐包分支；不指定随机命中，不替代实际新局面 |

规则覆盖基础战斗、费用与部分 build 255790 猎人牌效。模型出牌和攻击动作由主机再次校验：只有 Verified 且合法才显示动作；Conditional/Unsupported 移除动作并显示风险；Invalid 拒绝。确定斩杀只来自完整覆盖的规则结果。全为 choose 的动作组单独验证，界面标为“选择范围已验证”，并保留“未模拟选择后效果”的风险；选择与出牌混合的序列仍不支持。

当前回合与选择任务模板分别为 `hunter-v25/turn`、`hunter-v25/choice`；其它任务基础模板为 `hunter-v7`。策略保留熔岩猎犬、爆炸陷阱和武器的观察边界，并要求神秘恐魔按同一相关分支比较见证顺序、场面和治疗；截断、前缀或保留的普通就绪字段不能作为权威后继状态或斩杀依据。结束回合的模型动作必须以我方玩家实体 ID 为来源、不能带目标；模型解析、工具参数和最终主机验证使用同一约定。候选身份经过统一的视角、稳定性、数量及实体冲突边界，观战时不外发私有手牌、奥秘、牌库组成或私有事件身份。起始参考接线最初属于preview16之后的源码更新，当前preview26已包含该能力。

最终建议与归档用 `LimitationsVersion=1` 区分新增结构。`Assumptions`、`Unknowns`、`UnsupportedMechanics` 保存模型意见，每类最多 12 条；`HostRisks`、`HostAssumptions`、`HostUnknowns`、`HostUnsupportedMechanics` 只来自最终所选动作的本地验证，每类最多 64 条，每条最多 2000 字。主机条目、文字或脱敏扩张超过上限时设 `HostLimitationsTruncated`，界面和兼容风险摘要明确提示截断。兼容 `Risks` 仍混合两种来源，但动作移除说明、截断提示及本地限制优先，不会被模型的 12 条风险挤掉。结构化字段按既有归档规则脱敏并深只读；CLI 输出使用归档后的字段，并报告各类数量及截断状态。

本地验证没有单独提供的类别保持 `null`；已枚举但未列出项目用空数组，两者都不表示整个机制已经完整覆盖。现有 Line/Choice 结果未单列 Unknowns，不能把任意风险文字猜成这一类。旧记录没有版本和类别时显示“旧记录未区分”，不据兼容风险补造来源；新增字段省略 null 和默认截断值，旧归档重存保留原内容哈希。连续追问仍仅承接受限的历史摘要意见，不把旧限制当成本轮事实。

下水道之王的起始边栏参考由主机从原历史会话或已经固定的日志来源取得已保存套牌，不从当前选择器、编辑草稿或模型上下文 JSON 推测。`StartingDeckContext.FromSavedDeck` 核对保存版本 ID、牌码与定义一致性，`StartingDeckBinding` 绑定 match、state、event、分析 build 并深冻结全部牌表；缺失、范围或追踪冲突时不返回该参考。原套牌创建 build 可以早于本局固定 build，参考身份按本局卡库的 DBF 查询，缺项不借当前候选回填。`InitialReference` 返回 `IsSessionBound`、`DeckVersionId`、`CardBuild`、原始张数和卡牌；本地选择窗口显示原版本及逐张份数。它只证明本局记录的原始牌码参考，不证明实际完整当前池、消耗或复制／偷取来源的继承，不能把初始三张减去已选次数当成余量。

历史清理保留仍存在的固定复盘；删除当前复盘时同步清理显示、重绘当前源并使旧本地计算失效。只要实际删除了对局，就在下一次异步等待前废弃在途历史／笔记读取，避免旧结果在分页刷新前重新发布已删除局面；删除零局不做这一额外失效。清理不会扩大到套牌、笔记或建议归档。

桌面与 CLI 共用 Agent 的工具来源 ID 预检：在本批任何工具回调之前拒绝非法、重复、带地址或回显本次凭据的 ID，既不把它们写入工具审计，也不丢弃已发生的 HTTP 用量。这不表示所有工具参数或效果具备整批事务语义。

围绕“野兽快”已增加苦花骑士、振翅守卫的灌注战吼、幽爪熊的入场与原生灌注亡语。已有巨狼祝福且观察到一致可靠的当前参数时可计算强化；仅有一个已确认、当前攻击力与费用已知的野兽候选时，技能的加攻和减费才有确定结果。首次技能替换的强度或可用状态不明时保留条件，不凭印刷初值补齐。

奇异训犬师可计算入场、直接抽牌范围和有证据的后置灌注，但不猜抽到的野兽；花木护侍依据明确累计灌注判断是否抽两张，缺计数仍保留范围，不从技能等级推算。震地雷龙可给已知当前属性的手牌/牌库随从结算 +3/+3，隐藏目标保持未知；已审计的纯属性附魔使用观察值，不重复叠加。原生发现入口和部分实际选择生命周期已有覆盖，完整发现池、拼装主目标及新实体映射、旧局面回溯、复杂随机与奥秘交互仍未完成，不能据此宣称整套牌已可完整模拟。

牌库跟踪需要从开局持续观察且与确认套牌一致。晚接入、缺口和未知洗入会保留未知量，已知数量可能退化为下限，不伪造精确概率。对手台账记录公开的 HAND→PLAY 事件，回手后再打分别记录；衍生物不自动算作打出的牌，未知身份不使用未来信息回填历史。

默认每次分析最多 2 轮工具交互、总计 8 次工具调用、30 秒，每次 HTTP 输出上限 1500 令牌；按 MatchId 默认限制 60 次 HTTP 请求、200000 令牌、1 个并发。工具总调用上限为固定保护，其余可用上表配置。修改预算会先取消并结算现有请求，再恢复已经保存的消耗，不以调高或调低配置清零用量。

发送前预留用量，完成后按服务报告结算；实际报告可能超过预留，达到预算后拦截后续请求。未取得成功 HTTP 响应的请求释放令牌预留，但仍计请求次数；取得成功响应后，若缺少用量或无法解析正文，则按保守预留量计入，分析失败不一定代表没有消耗。匿名审计保存模型、build、任务/模板版本、用量、耗时和工具结果哈希；归档另存简短工具依据摘要，不保存完整提示、原始 HTTP 正文或密钥。重启恢复已记录消耗，连接检查不计入对局预算。赛前套牌分析使用对应套牌的独立预算标识。Storage 提供审计详情清理 API，桌面清理入口只清对局记录；两者都不会重置已消费预算。不显示未经核实的费用金额。

局面、来源、视角、套牌、配置或历史选点变化会取消旧请求，返回前再核对。模型故障不停止本地记牌。自动建议等待 1.2 秒稳定，并跳过回放与日志追赶的中间局面。

`advise --snapshot path --env .env --data-dir path --task turn --out advice.json` 可对手动指定的过滤快照请求分析；任务可用 mulligan、turn、choice、review、deckplan 对应五种模板，已结束局面默认使用 review。程序读取固定 build 的本地卡库，使用紧凑上下文和主机动作复验，完成后归档建议；输出文件保留结构化 Advice 格式，控制台显示验证、动作数量、历史承接与知识截止、限制分类、耗时和用量摘要。该命令仍要求有效过滤快照；不等同于桌面中无需实时局面的独立套牌计划入口。

CLI 仅在本地找到同 MatchId、EventSequence、StateVersion 且内容一致的稳定完整保存决策点时，才开放个人计划/历史工具，并用其真实录制时间固定 `KnowledgeAsOf`。套牌绑定与卡库取自该决策点的原始会话；旧快照缺 tracking 或 ClientBuild 时也可恢复原始来源，显式矛盾则在调用模型前拒绝。套牌版本的创建 build 不代替原对局 build。连续追问复用桌面的最多四轮筛选：同对局、套牌、卡库、状态/事件边界及不晚于本次知识截止的旧模型意见。查询 `AsOf` 单独固定为请求开始时间，因此后来针对同一旧局面生成的解释仍可承接，不能把它们当作当前事实。未匹配或改过内容的外部快照没有个人库、历史对话或伪造的知识截止。

请求审计保留模型、运行、请求、事件、套牌与模板来源；工具审计保留对应的模型、运行、请求、工具调用标识及结果哈希。提供方的工具调用标识在整批执行前校验：必须满足审计的 1–200 字符匿名 ASCII 标识边界，不带地址或本次凭据；非法标识安全拒绝且不回显，已发生的 HTTP 用量仍会持久化。预算从持久化审计恢复，采用 `.env` 与已保存调优合并后的上限，Ctrl+C 仍刷新已经观察到的用量和工具耗时。输出不能覆盖输入快照、模型配置或所用数据库。

CLI 接受 Core 为已确认视角匿名化的敌方 SECRET 槽公开分类：仅 `SECRET`、`QUEST`、`SIDE_QUEST` 的 `0`、`1` 或 `unknown` 值。隐藏 CardId、私有牌效标签、非 SECRET 区域、未知归属或未确认视角均不据此放开。模型接收的仍是过滤后的固定上下文。

当前己方选择的候选还可位于 SETASIDE、DECK 等区域，CLI 通过 `ChoiceVisibility.IsProjectedCurrentOptionEntity` 核对当前已确认就绪选择、精确实体对象、候选身份／归属及 Core 原匿名投影标签，接收解析器已公开的候选。此资格不按区域名通行；普通隐藏牌、对方或未就绪选择、身份冲突及额外私有标签仍在 HTTP 前拒绝。精确历史匹配时才向 `evaluate_choice` 提供原会话起始参考；仅有 tracking 背景的外部快照不因此升级为会话绑定。

其他命令包括 config-preview、replay、watch、cards-import/search、deck-decode、pool-sync/import、historical-context 和 stats；运行 help 查看参数。record 共享读取并固定完整行边界，Ctrl+C 保存已观察部分。diagnose/config-preview 只读。沙箱可能重定向 LocalApplicationData，可用 diagnose --config 指定实际文件。

## 桌面自动化连接与鼠标卡顿排查

2026-11-01，preview28 首次打开、尚未监听时，用户报告鼠标在窗口内几乎无法移动。原进程采样 5066 毫秒消耗 5031 毫秒 CPU。软件绘制测试在后台静置时曾显示零 CPU，但前台再次出现持续开销，用户确认鼠标仍卡；不能用后台静置结果替代真实前台输入验收。

托管线程栈显示界面线程停在正常消息循环，原生热点线程采样落在 `UIAutomationCore.dll`。断开本次 `computer-use` 的 `sky` 诊断连接（重置其 Node 会话）后，同一批测试进程五秒采样均为零 CPU，用户随即确认鼠标恢复流畅；重新打开未修改的 preview28 后五秒 CPU 也为零，窗口正常响应。此记录指向本次外部 UI Automation 连接的干扰，不将其归因为日志监听或模型请求，也不据此断言所有辅助功能客户端都有问题。

软件绘制及关闭触控／笔支持仅用于隔离测试，未解决该鼠标问题；产品源码已恢复原渲染／输入行为，仍使用 preview28，保留正常无障碍支持及原发行包。后续桌面验收结束应断开自动化连接，并让用户在无诊断连接时验证真实鼠标移动。诊断工具和合成数据只保留在忽略的 `.local` 目录，未读取真实对局或调用模型；清理只关闭合成测试进程，个人数据保留，随后重新打开正式 preview28。
