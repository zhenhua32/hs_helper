本清单执行[第一版功能与技术设计](v1-design.md)。第一版完整覆盖赛前、赛中和赛后，开发顺序先验证国服日志，再建立可回放状态，随后接入计算和 Agent，最终贯通桌面界面。

已接入版本化用户计划/笔记、关键回合标记、建议归档、截止时刻个人查询、五类任务模板和紧凑中文上下文；中文双方局面、本地计算、日志配置/重建、局面时效区分和最多四轮连续追问也已有桌面入口。实现与离线回归不等于 M0 游戏画面对照或发布验收，本文不据此宣布第一版全部完成。

## M0 国服日志验证

目标是确定当前客户端能够可靠提供哪些局面信息，并产出后续开发使用的样本与字段映射。

- [x] 确认本机安装目录、日志会话、Power 配置和日志中的客户端 build 来源。
- [x] 为需要修改的日志配置准备预览、备份和恢复流程。
- [ ] 使用常用的 1 至 2 套猎人记录完整对局，保存套牌版本。
- [ ] 覆盖留牌、抽牌、出牌、攻击、结算、选择与对局结束。
- [ ] 验证动态费用、法力、攻击状态、公开身份和选择项的日志来源。
- [ ] 确认是否提供可使用的动作或目标信息，并记录覆盖范围。
- [ ] 对照游戏画面标注关键时刻的预期局面，整理去身份化日志样本。
- [ ] 记录缺失字段、日志重复、会话切换、重连或回溯等特殊行为。

验收条件：样本能够明确回答每个关键字段来自哪里、何时可用、何时应标记未知。未验证能力不能作为精确计算的前提。当前实测记录见[国服日志验证记录](log-compatibility.md)。

- [x] 创建 .NET 10 桌面工程，建立界面、状态、基础设施和 Agent 的模块边界。
- [x] 建立卡库 SQLite 初始数据结构和 schema 版本。
- [x] 完成后续 schema 迁移流程及对局等数据表。
- [x] 实现卡牌按版本和语言下载、校验、暂存、切换及失败回退。
- [x] 建立 CardId 与 dbfId 映射，支持猎人、中立、其他职业及关联衍生牌查询。
- [x] 持久化与查询带 build、模式、生效区间和来源的卡池规则，支持系列/单卡、禁用与未上线集合的显式导入。
- [x] 同步官方标准系列成员证据并映射固定 build；资料不完整或失效时保留 Unknown。
- [ ] 自动取得并核对当前国服完整上线、临时禁用与核心调整证据。
- [x] 支持中文名称与效果文本搜索。
- [x] 增加关键词筛选和图片缓存。
- [x] 接入版本 1 牌码编解码并保留边栏，支持保存套牌 JSON 记录。
- [x] 实现数据库套牌历史和版本查询。
- [x] 检查已知职业、普通 30 张/同名牌数量和有效规则卡池，缺数据、构筑例外及特殊边栏规则明确报告 Unknown。
- [ ] 完整覆盖当前国服的特殊构筑例外与边栏容量规则。

验收条件：断网时仍可使用已有完整卡库；失败下载不会覆盖活动数据；导入套牌能正确关联卡牌与版本，未知结构明确报告。

- [x] 归档完整结构化建议及其局面/事件/版本绑定，提供针对性回归与合成链路样本。

验收条件：已验证计算能追溯到工具结果；未覆盖效果显式报告；模型无法引用不存在的手牌作为有效动作。局面变化、超时、断网或模型错误不会中断本地记牌。

模型评估使用相同局面样本，比较规则与工具使用是否正确、建议是否有依据、响应速度和实际费用。策略优劣通过人工复盘和后续实战观察评估，单场胜负不作为建议正确性的唯一依据。

## 发布前验收

以下保留为发布级验收清单，不因功能代码或合成检查已经落地而自动勾选。具体执行结果以对应日期的验证记录为准。

- [ ] 起手、抽牌、场面、回合和结束状态通过真实日志对照。
- [ ] 同名牌通过实体区分，动态费用和未知属性处理正确。
- [ ] 已知洗入、未知洗入及记录缺口不会导致虚假的精确概率。
- [ ] 规则覆盖范围有记录，关键计算与合法性检查有针对性的回归样本。
- [ ] 复盘查询被限制在对应决策时刻已知的信息。
- [ ] 过期建议无法继续显示为当前可执行步骤。
- [ ] 卡库更新失败、模型故障和调用超限都有可用的界面行为。
- [ ] 模型延迟、调用量和费用有实测记录，配置上限生效。
- [ ] API 密钥受到保护，发送上下文和排查日志按设计处理身份字段。
- [ ] 文档准确反映实际能力、已覆盖牌效和剩余兼容性问题。

## 当前代码缺口与下一轮

已补齐中文分区局面与英雄资源、本地计算、停止/停更时效区分、日志配置与重建、连续追问及建议/模型请求关联。客户端 build 同步已有按钮，Windows 自包含发布、完整性校验与无窗口诊断已有脚本。功能入口、打包脚本与真实可用性分别验证，不据此提前勾选发布前验收。

仍需继续实现和完善整套常用猎人的复杂牌效，以及特殊构筑与边栏规则。真实国服画面对照、重连/回溯、多屏/DPI、五类任务的真实建议质量和干净 Windows 发行启动仍需取得实测证据。发布流程见 [Windows 发行说明](windows-release.md)。

当前公开来源尚不能证明固定 build、国服地区的完整标准构筑合法性；系列分类、公布和上线不是同一件事。特殊构筑也须另建规则，例如官方说明的[古神数量限制](https://hearthstone.blizzard.com/en-gb/news/24304163/reign-of-the-black-empire-is-now-live)。无法核实的项目继续保留 Unknown，不根据系列成员或核心牌名前缀推断合法。

下一项工作继续 M0 国服画面对照，扩展“野兽快”的复杂牌效，并验收五类建议、计划/笔记与归档在真实模型和桌面实战中的完整流程。计划与笔记查询已有实现；多屏/DPI、复杂效果完整覆盖和真实建议质量仍未完成。标准系列成员证据已接入，但禁用和上线信息不完整，合法性继续保留 Unknown。
